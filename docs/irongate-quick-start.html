Verify captive access
without changing your LAN

Run the automated HTTPS portal, RADIUS authentication and accounting demonstration on a Linux workstation. No gateway appliance or second physical NIC is required.

Scope This is the current one-client development lab, not a production gateway installation. Test networking, certificates and backend services stay inside a disposable VM. The automated run needs no console login.

1 Before you begin

HostLinux x86-64 with usable KVM (/dev/kvm). Allow four virtual CPUs and 8 GiB guest RAM, plus host headroom.
ToolsRust 1.100+, Cargo/rustup, just, Python 3.11+, qemu-system-x86_64, qemu-img and cloud-localds.
Storage / networkSpace for cached images and fresh 32 GiB virtual overlays. Internet access for dependency/image downloads and first-time guest package preparation.

Run commands from the IronGate repository root. If the Rust target or Cargo dependencies are not already cached:

rustup target add x86_64-unknown-linux-musl
cargo fetch --locked

Note: The project does not install missing host tools or repair KVM permissions automatically. Use the repository’s docs/qemu-first-boot.md for host setup background.

2 Prepare the lab images once

just vm-lab-prepare
just vm-portal-prepare
just vm-https-prepare
just vm-radius-prepare

Run these in order. They build on the pinned Debian image and prepare separate guest images. Preparation uses QEMU userspace NAT to download guest packages; it creates no host bridge or TAP device. Existing verified prepared images are reused.

3 Run the complete accounting demonstration

just vm-accounting-test

The command builds the static daemon, boots a fresh overlay, runs the guest browser and backend tests, retains evidence, then powers off the VM. Test boots use -nic none; workstation interfaces, routes, firewall and trust settings are unchanged. Run one VM test at a time.

4 Verify successful operation

The final console line must begin with passed: and identify a report.json. A completed accounting run passes 18 scenarios, including these checks:

CheckExpected result
Join and sign inDHCP gives 10.50.10.100; upstream transit is blocked before login and available after a valid RADIUS Accept.
Account and disconnectMatching Start / Interim / Stop records; directional totals agree with the independent workload; logout blocks access immediately.
Lose the accounting backendBacklog becomes visible and new admission pauses. Existing access retains its original expiry. Requested logout still works; pending Stop drains after recovery.
Guard the packet pathSpoof attempts and kernel bypass are blocked. HTTPS certificate and bounded-worker checks pass.

Open the directory printed by the command:

target/vm/packet-lab/runs/RUN_ID/

Replace RUN_ID with the printed run identity. Inspect report.json, serial.log, evidence.log and the three portal-*.png screenshots. Reports record source revision, dirty state, binary identity and individual outcomes. A new run does not automatically include the separately collected release quality bundle.

5 Know the configuration boundary

Automated lab settings

The harness generates private HTTPS/RADIUS configuration and fresh test secrets inside the guest. It uses this accounting block:

accounting = "radius"
accounting_endpoint = "192.0.2.80:1813"
accounting_interim_seconds = 2

Portal and test identity

Guest portal: https://10.50.10.1:8443
Test user: lab-user
Test password: lab-pass

The harness signs in automatically with normal certificate verification. The portal is not exposed to your workstation browser. These are public fixture credentials, not appliance login credentials.

Important: This native lab TOML is distinct from the example deployment profiles. ig config check validates those profiles offline; ig doctor currently checks host interfaces, not live RADIUS/accounting health. Normal gateway deployment is still pending.

6 Resolve common startup issues

SymptomAction
KVM inaccessible / tool missingVerify installed host prerequisites and access to /dev/kvm. An agent sandbox may need approval for the QEMU command.
Missing prepared manifestRun all four preparation commands in Step 2, in order.
Offline build lacks a crateRun cargo fetch --locked with network access, then rerun the test.
Image digest mismatchKeep the failed evidence and investigate the modified image. Do not bypass the digest check.
Failed scenario / no final resultRead report.json and the retained logs. Reproduce with a fresh run; keep the failed run for comparison.

Operational limit: Accounting has four fixed lifecycle slots and bounded retries. Its outbox is memory-only; pending records may be lost on a crash. Protocol acknowledgments do not establish durable billing or production capacity. Keep guest disks, seeds and private configuration out of public evidence bundles.
